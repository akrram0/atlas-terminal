## 1. Goals and constraints

User-visible goals:

1. The connected prompt (`╭─ ... ╰─➜`) must render at a normal stroke weight,
   not a 1px hairline.
2. A WSL tab must show the active distribution's own icon instead of the
   generic Ubuntu mark.

4. Preserve earlier fixes: Ctrl+K palette, Ctrl+V paste, smart Ctrl+C, Classic
   theme, URL panic fix, rounded prompt corners, updater.

Hard constraints:

- No Unicode or emoji UI icons. Only embedded SVGs (`assets/icons/*.svg`,
  `gpui::svg`, `AssetSource`), tinted with `currentColor`.
- Never take control of the desktop: no SendKeys, GUI automation, screenshots,
  focus stealing, or simulated clicks.
- Verification is via unit tests, isolated Rust harnesses, CI, app logs, and
  user visual confirmation.
- No Windows Rust toolchain locally; the full build is CI-only.

## 2. Prompt stroke weight (`src/terminal/procedural.rs`)

### 2.1 Problem

`procedural_cell` painted box-drawing lines at 1px (light) and 2px (heavy).
At the live settings (`font_size: 14.0`, line height 1.2 -> roughly 17px cell)
the prompt frame looked like a hairline. An earlier idea to derive thickness
from cell height (`lh / 16`) was rejected because it still yields 1px at 17px,
which would not fix the complaint.

### 2.2 Final design

- Light strokes are a fixed `2.0` logical px; heavy strokes are `3.0`.
- Constants live inside `procedural_cell` as `let light = 2.0; let heavy = 3.0;`
  with a comment explaining that weight must not collapse at small cells.
- Every box-drawing arm passes `light` or `heavy`; block elements, quadrant
  blocks, shades, and eighth blocks are unchanged.
- Rounded corners (`U+256D..U+2570`) use the same `light` thickness for their
  two straight arms and their quarter arc.

### 2.3 Centring fix

The old helpers were exact only for `th = 1.0`:

```
old hline: y in cy + 1.0 - th .. cy + 1.0
old vline: x in cx + 1.0 - th .. cx + 1.0
```

With a 2px stroke, that put the line 0.5px off the arc centre line, producing a
small jog at the join. New helpers centre every stroke on the same spine as the
arcs:

```rust
let hline = |rects: &mut Vec<(f32, f32, f32, f32)>, x0: f32, x1: f32, th: f32| {
    let y = cy + 0.5;
    rects.push((x0.min(x1), y - th / 2.0, x0.max(x1), y + th / 2.0));
};
let vline = |rects: &mut Vec<(f32, f32, f32, f32)>, y0: f32, y1: f32, th: f32| {
    let x = cx + 0.5;
    rects.push((x - th / 2.0, y0.min(y1), x + th / 2.0, y0.max(y1)));
};
```

For `th = 1.0` this is byte-identical to the old geometry. Square corners and
tees keep their existing start/end offsets (`cx +- 1.0`, `cy +- 1.0`), so heavy
arms still overlap the light arms.

### 2.4 Arc rasteriser

`arc_stroke` gained a `thickness: f32` parameter. Each sampled point emits a
quad of that thickness centred on the arc point:

```rust
let half = thickness / 2.0;
...
rects.push((x - half, y - half, x + half, y + half));
```

All four rounded corners pass `light`. The arc geometry itself (centre, radius,
start/end angles) is unchanged. The radius still comes from
`r = (cx - 0.5).min(cy - 0.5).max(1.5)`, and the arc centres remain
`sx = cx + 0.5`, `sy = cy + 0.5`, which is why the new line helpers use the
same coordinates.

### 2.5 Render path

`procedural_cell` is only used for glyphs classified as `CharClass::Block` in
`src/terminal/element.rs`. Those rects are painted directly as GPU quads:

```
window.paint_quad(fill(Bounds::from_corners(...), color))
```

No font glyph is involved, so the stroke width is exactly the logical pixel
value above (subject only to display scaling and antialiasing).

### 2.6 Tests (`src/terminal/procedural.rs`)

  than 10 rects and stay inside the relaxed cell bounds.
- `square_corners_stay_square` - `U+250C` still produces exactly 2 rects.

Added:

## 3. WSL distro detection (`src/wsl.rs`, new)

### 3.1 Public API

```rust
pub struct Distro {
    pub name: String,   // registry DistributionName, e.g. "archlinux"
    pub title: String,  // menu label, e.g. "Arch Linux"
    pub icon: &'static str, // e.g. "icons/arch.svg" (crate::icons::ARCH)
}

pub fn default_distro() -> Option<&'static Distro>;
pub fn icon_for_name(name: &str) -> &'static str;
pub fn title_for_name(name: &str) -> String;
```

`default_distro` is cached in `static DEFAULT_DISTRO: OnceLock<Option<Distro>>`,
so the registry is read once per process. A distro change while the app is
running is not picked up until restart.

### 3.2 Windows detection (no subprocess)

Registry root: `HKCU\Software\Microsoft\Windows\CurrentVersion\Lxss`.

Flow:

1. `RegOpenKeyExW(HKEY_CURRENT_USER, LXSS, 0, KEY_READ, ...)`.
2. Read `DefaultDistribution` (`REG_SZ`, a GUID with or without braces).
3. Normalise braces, open `Lxss\{GUID}`.
4. Read `DistributionName`.
5. If any step fails, enumerate subkeys with `RegEnumKeyExW` and take the first
   subkey whose `DistributionName` is readable.

FFI details:

- Raw `advapi32` declarations: `RegOpenKeyExW`, `RegQueryValueExW`,
  `RegEnumKeyExW`, `RegCloseKey`.
- `HKEY` is modelled as `isize`; `HKEY_CURRENT_USER` is
  `0x8000_0001u32 as i32 as isize` (sign-extended, as Win32 defines it).
- `KEY_READ = 0x20019`.
- A `Key(Hkey)` RAII guard closes handles on every return path.
- `read_sz` first queries the size with a null data pointer, then allocates and
  reads; it accepts only `REG_SZ` and non-empty values.
- `wide_string` decodes UTF-16LE bytes and stops at the first NUL unit.
- Non-Windows `detect_default()` returns `None`; the FFI module is
  `#[cfg(windows)]`.

## 9. Known limitations and risks

1. **Detection is cached for the process lifetime.** Switching the default WSL
   distro while Atlas is running requires a restart.
2. **Only the default distro is detected.** All WSL tabs use the same mark; a
   per-session distro picker is future work.
3. **Fallback may pick an arbitrary distro.** If `DefaultDistribution` is
   missing or unreadable, the first subkey with a readable `DistributionName`
   wins, which may not be the user's intended active distro.
4. **`REG_SZ` only.** `read_sz` rejects other value types; the subkey
   enumeration fallback normally covers this, but an unusual hive could still
   yield `None`.
5. **FFI assumptions.** `HKEY` as `isize` and the sign-extended
   `HKEY_CURRENT_USER` are correct for Win64. Detection runs under the user's
   own registry view; no WOW64 redirection is expected for
   `HKCU\...\CurrentVersion\Lxss`. CI compiled and smoke-tested the code but
   did not assert the registry result.
6. **Visual weight is not automated.** Tests assert 2px/3px rect geometry, not
   the perceived weight at a specific DPI scale. The user's confirmation is the
   acceptance signal.
7. **No delta patch for v0.1.48.** Users on older versions download the full
   installer. This is by design when non-exe assets change.
8. **Formatting drift is pre-existing.** See section 7.4.

  manifest. Instead, revert the feature commit's code while keeping a bumped

  version bump before pushing a rollback release.
- The previous release (`v0.1.47`) and its assets remain untouched.
- CI publishes from `main` only. Tag pushes are not rebuilt; see
  `.github/workflows/native.yml`.
