## 1. Goals and constraints

1. **"Confirm before closing active process" does nothing.** Closing a tab or
   the window with a running shell must ask first.
2. **The font picker is unwanted / broken** ("the fonts ... just remove it").
3. **fastfetch inside WSL shows no terminal name.** It must report Atlas.

Hard constraints that stayed in force:

- Preserve all prior fixes: full-bleed maximized acrylic, readable translucent

- Never take control of the desktop: no SendKeys, GUI automation, screenshots,
  or focus stealing.
- No Windows Rust toolchain locally; CI is the authoritative build.
- One release per version, published from `main` by the existing workflow.

## 2. Bug 1 - `confirm_close_process` was a dead setting

### 2.1 Root cause

`confirm_close_process` existed only in `config.rs`, the settings JSON and the
Settings toggle. Nothing in the close paths read it:

- tab close (`close_tab` in `src/view.rs`) removed the tab immediately;
- the window close button posts `WM_CLOSE` (`main.rs::window_button`), and
  nothing intercepted it.

The setting was therefore inert, exactly as reported.

### 2.2 Fix

**Tab close** (`src/view.rs`):

- `close_tab` (line ~707) now checks
  `app_settings.confirm_close_process && tab_is_live(index)` and, if both hold,
  stores `pending_close_tab = Some(index)` and returns without closing.
- `tab_is_live` (line ~724) treats a tab as live when any pane has
  `exited == false` (the shell has not emitted `Event::Exit`).
- The old body moved verbatim to `close_tab_now` (line ~738), which is the
  unconditional path used by the dialog. This keeps palette, tab-X and
  Ctrl+Shift+W callers on the same policy with no per-caller changes.
- Closing the last remaining tab still spawns a fresh tab (pre-existing
  behaviour), now using the configured default profile instead of hardcoded
  PowerShell.

**Window close** (`src/view.rs::new`, line ~313):

- `Window::on_window_should_close` is registered once at startup. When a close
  is requested and the setting is on with at least one live pane
  (`has_live_processes`, line ~732), it sets `pending_close_window = true`,
  notifies, and returns `false` so the platform keeps the window alive.
- Confirming calls `window.remove_window()`, which marks the window removed and
  bypasses the should-close callback (GPUI 0.2.2 semantics: the callback is
  only consulted for an external close request).
- The updater is unaffected: `updater.rs` restarts via `std::process::exit(0)`
  (lines ~1636 and ~1863), which does not go through `WM_CLOSE`.

**Dialog** (`src/view.rs`):

- `confirm_close_dialog` (line ~2121) renders a small panel over the standard
  `overlay_backdrop` (id 5, topmost): title/body depend on tab vs window,
  Cancel and a danger-accented Close button.
- `confirm_pending_close` (line ~775) and `cancel_pending_close` (line ~787)
  own the state transitions; both restore focus with `focus_main`.
- Enter/Esc are handled at the top of `handle_key` (line ~1738). The dialog is
  modal: every other keystroke is swallowed so nothing leaks into the shell.
- Clicking the backdrop cancels.
- While open, the dialog is painted after every other overlay (line ~3395), so
  it also wins over the palette, rename and settings surfaces.

No new icon glyphs were needed (text buttons only).

## 3. Bug 2 - font family picker removed

The Appearance tab hardcoded five family names and wrote them through
`set_font_family`. Only those five could ever be selected, the list did not
reflect installed fonts, and the user asked for it to go.

Changes (`src/ui/settings.rs`):

- Removed the `Font family` row, its hardcoded `fonts` array, and
  `AtlasView::set_font_family`.
- Kept **Font size** and **Line height**, which do work.
- The saved `font_family` is still loaded at startup
  (`AtlasView::new` -> `resolve_terminal_font`) and written back by
  `sync_and_save_settings`, so existing configs keep their family and no
  migration is needed. There is simply no in-app picker any more.

## 4. Bug 3 - no terminal name in WSL (fastfetch)

### 4.1 Root cause

Atlas already sets `TERM_PROGRAM=Atlas` and
`TERM_PROGRAM_VERSION=<cargo version>` for its child processes
(`src/session.rs`). That works for Windows programs, but a WSL profile spawns
`wsl.exe`, which starts a Linux process with a **clean environment**: variables
set on `wsl.exe` do not cross the boundary unless they are listed in `WSLENV`.
Inside the distro `TERM_PROGRAM` was therefore unset, and fastfetch's Linux
terminal detection (`terminalshell_linux.c`, the `getenv("TERM_PROGRAM")`
branch) had nothing to report.

### 4.2 Fix (`src/session.rs`, line ~276)

For `Profile::Wsl` only, the spawn now appends
`TERM_PROGRAM`, `TERM_PROGRAM_VERSION`, `COLORTERM` and `TERM` to `WSLENV`
with the `/u` flag (Win32 -> WSL direction), preserving any inherited
`WSLENV` entries. Duplicate detection strips existing flags, so an entry that
is already present as `NAME` or `NAME/p` is not duplicated.

### 4.3 Empirical verification (this machine, before the release)

```powershell
$env:TERM_PROGRAM='Atlas'; $env:TERM_PROGRAM_VERSION='0.1.51'
$env:COLORTERM='truecolor'; $env:TERM='xterm-256color'
$env:WSLENV='TERM_PROGRAM/u:TERM_PROGRAM_VERSION/u:COLORTERM/u:TERM/u'
wsl.exe -e bash -lc 'echo TP=$TERM_PROGRAM TPV=$TERM_PROGRAM_VERSION CT=$COLORTERM TERM=$TERM'
```

Output: `TP=Atlas TPV=0.1.51 CT=truecolor TERM=xterm-256color`.
Without `WSLENV` the same command prints empty values for all four, which
confirms the mechanism. `fastfetch --structure terminal --logo none` then
prints:

```
Terminal ❯ Atlas 0.1.51
```

`/u` was tested explicitly; plain entries also work, but `/u` documents the
intended one-way flow.

## 5. Two more dead settings fixed while auditing

- **Start directory** (`src/view.rs`, line ~652): `"current"` now spawns a new
  tab in the active pane's polled working directory (falling back to home). An
  explicit CLI directory still wins. `"home"` is unchanged.
- **Scrollback lines** (`src/session.rs`): the value is passed into
  `Session::spawn`, used for `alacritty_terminal`'s `scrolling_history`, and
  stored as `scrollback_limit` so inline-image pruning uses the same limit
  instead of the old hardcoded 10,000.

`startup_mode` ("Restore last session") is still inert: there is no session
persistence layer, and implementing one is a feature, not a setting fix. It is
listed as a known limitation rather than silently claimed as fixed.

## 8. Known limitations / follow-ups

- `startup_mode` remains unimplemented (no session restore).
- The confirm dialog treats every non-exited shell as a live process, so with
  the setting on it asks on every tab close. That is the literal meaning of the
  setting; a future refinement could track "busy" processes separately.
- The dialog is modal for the terminal surface. If Settings is open, its own
  Esc handler closes Settings first; the dialog remains and can still be
  answered with the buttons (or a second Esc). Buttons always work.
- Font family can only be changed by editing `settings.json` now; the family
  is still honored at startup by design.
