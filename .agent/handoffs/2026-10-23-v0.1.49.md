## 1. Goals and constraints

User-visible goals:

1. **Git Bash must launch Git for Windows**, not a WSL distro.
2. **Maximized windows must look at least as blurred/frosted as small ones.**
3. **OpenCode's input box must not show sharp square corners in translucent
   mode.**

Hard constraints:

- No Unicode or emoji UI icons; only embedded SVGs.
- Never take control of the desktop: no SendKeys, GUI automation, screenshots,
  focus stealing, or simulated clicks.
- Verify through unit tests, isolated Rust harnesses, CI, app logs, and user
  confirmation.
- No Windows Rust toolchain locally; CI is the authoritative build.
- Preserve all previous fixes (Ctrl+K palette, Ctrl+V paste, smart Ctrl+C,
  Classic theme, URL panic fix, rounded prompt corners, updater, WSL icons).

## 2. Bug 1 - Git Bash opened WSL

### 2.1 Root cause

The old spawn candidates were:

```rust
Profile::GitBash => vec!["bash.exe".into(), "C:\\Program Files\\Git\\bin\\bash.exe".into()],
```

`bash.exe` is resolved through `PATH`, and on this machine:

```
where.exe bash
C:\Users\Neweye\AppData\Local\Microsoft\WindowsApps\bash.exe
```

That path is the Microsoft Store **WSL launcher**, not Git for Windows. Because
it was first in the candidate list, `portable-pty` spawned it and the Git Bash
profile opened the default WSL distro (Arch Linux here).

Evidence gathered before the change:

```
C:\Program Files\Git\bin\bash.exe -> True
C:\Program Files (x86)\Git\bin\bash.exe -> False
C:\Users\Neweye\AppData\Local\Programs\Git\bin\bash.exe -> False
C:\Users\Neweye\scoop\apps\git\current\bin\bash.exe -> False
C:\Windows\System32\bash.exe -> False

& 'C:\Program Files\Git\bin\bash.exe' -lc 'echo GITBASH_OK; uname -a; echo MSYSTEM=$MSYSTEM'
GITBASH_OK
... MSYSTEM=MINGW64
```

### 2.2 Fix (`src/session.rs`)

`Profile::GitBash` now uses `git_bash_candidates()`, which considers **only
explicit Git installations**:

```rust
fn git_bash_candidates() -> Vec<String> {
    let mut roots: Vec<PathBuf> = Vec::new();
    for var in ["ProgramFiles", "ProgramFiles(x86)"] {
        if let Some(dir) = std::env::var_os(var) {
            roots.push(PathBuf::from(dir).join("Git"));
        }
    }
    if let Some(dir) = std::env::var_os("LOCALAPPDATA") {
        roots.push(PathBuf::from(dir).join("Programs").join("Git"));
    }
    // Non-standard installs that expose `git.exe` on PATH: derive the Git
    // root from `<root>\cmd\git.exe`.
    if let Some(path) = std::env::var_os("PATH") {
        for dir in std::env::split_paths(&path) {
            if dir.join("git.exe").is_file() {
                if let Some(root) = dir.parent() {
                    roots.push(root.to_path_buf());
                }
            }
        }
    }
    roots.push(PathBuf::from(r"C:\Program Files\Git"));

    let mut candidates = Vec::new();
    for root in roots {
        for rel in [r"bin\bash.exe", r"usr\bin\bash.exe"] {
            let candidate = root.join(rel);
            if candidate.is_file() {
                let candidate = candidate.to_string_lossy().into_owned();
                if !candidates.contains(&candidate) {
                    candidates.push(candidate);
                }
            }
        }
    }
    candidates
}
```

Preference order: environment-derived Git roots first, standard
`C:\Program Files\Git` last; `bin\bash.exe` before `usr\bin\bash.exe`; existing
files only; deduplicated. The bare `bash.exe` name is never used, so the
WindowsApps WSL alias cannot win.

On a successful Git Bash spawn the app logs the winner:

```rust
if matches!(profile, Profile::GitBash) {
    crate::log_line(&format!("git bash: using {shell_used}"));
}
```

Expected on this machine:

```
git bash: using C:\Program Files\Git\bin\bash.exe
```

`--login -i` is still passed to Git Bash, so it behaves like a normal Git Bash
terminal (MINGW64, MSYS environment).

### 2.3 Why not just reorder the list?

A reorder to `["C:\\Program Files\\Git\\bin\\bash.exe", "bash.exe"]` would work
on this machine but still falls back to WSL on any machine where Git is
installed elsewhere. The resolver also handles per-user installs
(`%LOCALAPPDATA%\Programs\Git`), scoop-style installs exposed via `PATH`, and
32-bit installs.

## 3. Bug 2 - weaker acrylic blur when maximized

### 3.1 What Windows actually allows

Research summary (details and links in the v0.1.48 research notes and the
earlier session):

- `ACCENT_ENABLE_ACRYLICBLURBEHIND` (state 4) and
  `DWMWA_SYSTEMBACKDROP_TYPE = DWMSBT_TRANSIENTWINDOW` have **no blur-radius
  parameter**. DWM's blur radius is fixed. `AccentFlags` has no radius bit;
  the only app-controlled knob is `gradient_color` (an `AABBGGRR` tint).
- `DesktopAcrylicController` exposes `TintColor`, `TintOpacity`, and
  `TintLuminosityOpacity` - tint/luminosity only, still no radius.
- A real variable radius requires a host-backdrop brush plus a Direct2D
  Gaussian effect (`CreateHostBackdropBrush` + `DWMWA_USE_HOSTBACKDROPBRUSH` +
  `CLSID_D2D1GaussianBlur`). That is a large, composition-layer change with
  known resize/focus-loss risks; it was rejected for this release.
- Re-applying the accent on a visible window makes DWM briefly drop and
  re-enable the backdrop (Zed gpui PR #63134). Reapply only on state changes,
  never on every resize.
- Windows deliberately does not round maximized windows; pseudo-maximize is the
  only in-process way to keep rounded Atlas corners, and it was not needed for
  this bug.

The user's observation was **"still blurred but weaker"**, not "blur
disappears". The practical fix is therefore a stronger theme-matched tint veil
when maximized, plus a one-shot accent reassert after the transition.

### 3.2 Implementation (`src/main.rs`, `rounded_corners`)

New state:

```rust
static DARK_MODE: AtomicBool = AtomicBool::new(true);
static LAST_ZOOMED: AtomicBool = AtomicBool::new(false);
const WM_SIZE: u32 = 0x0005;
```

Tint calculation in `apply_composition_accent`:

```rust
let zoomed = unsafe { IsZoomed(hwnd) } != 0;
let alpha: u32 = if zoomed { 0x26 } else { 0x01 };
let rgb: u32 = if DARK_MODE.load(Ordering::Relaxed) {
    0x000000 // dark theme: black veil
} else {
    0xFFFFFF // light theme: white veil
};
AccentPolicy {
    accent_state: ACCENT_ENABLE_ACRYLICBLURBEHIND,
    accent_flags: 0,
    gradient_color: (alpha << 24) | rgb,
    animation_id: 0,
}
```

- Restored: `0x01000000` in dark mode, exactly the old nearly-transparent tint.
- Maximized: `0x26000000` in dark mode (about 15% black), `0x26FFFFFF` in light
  mode. The acrylic still blurs the desktop; the veil makes detail behind it
  less legible, which is perceived as stronger frost.
- `0x26` is the tuning knob. Raise it for a frostier full-screen look; lower it
  if it looks too dark.

`WM_SIZE` reasserts the accent once per state change:

```rust
WM_SIZE => {
    let zoomed = unsafe { IsZoomed(hwnd) } != 0;
    if LAST_ZOOMED.swap(zoomed, Ordering::SeqCst) != zoomed {
        let opacity = f32::from_bits(INITIAL_OPACITY.load(Ordering::SeqCst));
        if opacity < 0.999 {
            crate::log_line(&format!("backdrop: zoomed={zoomed}, reasserting acrylic"));
            unsafe { PostMessageW(hwnd, WM_APP_BACKDROP, 0, 0) };
        }
    }
    // Always forward WM_SIZE to gpui; returning 0 here would freeze the surface.
    let prev = ORIGINAL_WNDPROC.load(Ordering::SeqCst);
    if prev == 0 {
        unsafe { DefWindowProcW(hwnd, msg, wparam, lparam) }
    } else {
        unsafe { CallWindowProcW(prev, hwnd, msg, wparam, lparam) }
    }
}
```

`LAST_ZOOMED` is initialized in `apply()` after subclassing. Posting
`WM_APP_BACKDROP` (rather than calling `apply_backdrop` inline) keeps the
composition calls on the UI thread and defers them past the resize message.

`set_dark_mode` now records the theme luminance and re-applies the accent when
it flips:

```rust
pub fn set_dark_mode(dark: bool) {
    let previous = DARK_MODE.swap(dark, Ordering::SeqCst);
    let raw = MAIN_HWND.load(Ordering::SeqCst);
    if raw == 0 { return; }
    if previous != dark {
        unsafe { PostMessageW(raw as Hwnd, WM_APP_BACKDROP, 0, 0); }
    }
    // ... existing DWMWA_USE_IMMERSIVE_DARK_MODE write ...
}
```

The accent log now includes the tint:

```
composition accent: enabled=true, res=1, tint=0x26000000
```

### 3.3 Risks

1. **One-time flash on maximize/restore.** DWM drops and re-enables the accent
   when the policy is re-applied. It is deferred to the end of the transition
   and happens once per state change, but it may still be visible. This is the
   documented trade-off for repairing a stale/dropped accent.
2. **Tint is not blur.** The user may still perceive the blur radius as fixed
   (it is). If they want a true radius, the host-backdrop Gaussian path is the
   only real option.
3. **Darkening.** A 15% black veil on a dark theme is subtle but real. If the
   user dislikes it, lower `0x26` or revert the maximized branch to `0x01`.
4. **Light theme.** The veil switches to white via `DARK_MODE`. Verify if the
   user switches themes; `set_dark_mode` repaints the accent on the flip.

## 4. Bug 3 - OpenCode input box has sharp corners

### 4.1 Root cause

OpenCode v2.0.32 draws its prompt as a **filled rectangle of terminal cells**,
not with rounded border glyphs:

`packages/tui/src/component/prompt/index.tsx`:

```tsx
const promptBg = createMemo(() => theme.decrease(theme.background.raised.base))
...
<box
  border={["left"]}
  borderColor={borderHighlight()}
  customBorderChars={{ ...SplitBorder.customBorderChars, bottomLeft: "╹" }}
>
  <box
    backgroundColor={promptBg()}
    ...
  >
    <textarea ... focusedBackgroundColor="transparent" />
```

The bottom hairline is a half-block strip, gated on the fill alpha:

```tsx
customBorderChars={{
  ...EmptyBorder,
  vertical: promptBg().a !== 0 ? "╹" : " ",
}}
...
customBorderChars={
  promptBg().a !== 0
    ? { ...EmptyBorder, horizontal: "▀" }
    : { ...EmptyBorder, horizontal: " " }
}
```

There is no `╭ ╮ ╰ ╯` in the prompt component. The v2.0.32 `prompt` config
block only has behaviour keys (`editor`, `paste`, `image_preview`); the theme
schema has no corner/border-shape token. A terminal emulator cannot infer and
round an arbitrary cell rectangle, so this is **not fixable in Atlas** without
patching OpenCode.

### 4.2 Local workaround installed

OpenCode's own code checks `promptBg().a !== 0`, so a fully transparent prompt
background removes both the fill and the `╹`/`▀` hairlines. A theme was
generated from OpenCode v2.0.32's built-in
`packages/tui/src/theme/assets/v2/opencode.json` with two edits:

1. `base.background.raised.base` -> `"transparent"`.
2. `base["@dialog"].background.base` -> `"$hue.neutral.600"` so dialogs do not
   inherit the transparent fill.

Installed files on this machine:

```
%USERPROFILE%\.config\opencode\themes\atlas-glass.json
%USERPROFILE%\.config\opencode\tui.json   -> "theme": { "name": "atlas-glass" }
%USERPROFILE%\.config\opencode\tui.json.bak-atlas-glass
```

Repo copies/notes:

```
.agent/opencode/atlas-glass.json
.agent/opencode/README.md
```

Why this works: `decrease` only shifts colors that are present in the hue
index (`compileHueSteps` in `packages/theme/src/tui/resolve.ts`). `"transparent"`
resolves to `RGBA(0,0,0,0)`, is not in the index, and is returned unchanged, so
`promptBg().a` is 0. The prompt then paints no fill and uses spaces for the
hairlines. The left accent rail remains.

OpenCode must be restarted (or the theme selected in its UI) after installing.
This removes the sharp rectangle; it does not create a rounded box. If the user
wants a visible rounded box, the only real path is an upstream OpenCode change
(its prompt component already supports per-component `customBorderChars`, so a
rounded-border option is small).

### 4.3 Revert

```powershell
Copy-Item "$env:USERPROFILE\.config\opencode\tui.json.bak-atlas-glass" `
          "$env:USERPROFILE\.config\opencode\tui.json" -Force
Remove-Item "$env:USERPROFILE\.config\opencode\themes\atlas-glass.json"
```

Do not modify `tui.json` from Atlas at runtime; the user owns that config and
the running OpenCode process may rewrite it.

## 7. Known limitations / next steps

1. **Blur radius is fixed by Windows.** The fix increases perceived frost, not
   the radius. A true radius needs the host-backdrop + D2D Gaussian path.
2. **Maximize flash.** The one-shot accent reapply can flash. If unacceptable,
   remove the `WM_SIZE` reapply and accept the normal tint while maximized (or
   set the tint unconditionally).
3. **OpenCode theme is a local config change.** It is not shipped in the Atlas
   exe and is not applied by the updater. New machines need the theme file and
   the `tui.json` merge.
4. **No actual rounded corners in OpenCode.** Upstream change required; do not
   attempt cell-rectangle rounding in Atlas.
5. **Git Bash detection is Windows-only by design.** On non-Windows the
   candidate list is empty and the profile errors; Atlas is a Windows app.
6. **Release assets are verified.** Hashes are recorded in §5.1; the updater
   can serve both the delta and the full installer.
